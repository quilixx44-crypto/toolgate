Architecture

Functional requirements

  • Intercept every tool call before it runs and return allow, review or block with a reason.
  • Enforce per-agent tool permissions, parameter schemas and destination allowlists.
  • Decode obfuscated payloads before checking them.
  • Detect destructive commands, SQL abuse, data exfiltration, SSRF and prompt injection.
  • Hold risky calls in an approval queue until an admin approves or rejects them.
  • Log every decision; let admins view, filter and verify the log.
  • Measure accuracy, false-positive rate and latency on a labelled test set.

Non-functional requirements

  • Default deny: anything not explicitly allowed is blocked.
  • Low latency: inspection under 5 ms per call (p95).
  • Agents authenticate with hashed API keys; admins with signed session tokens.
  • Audit payloads encrypted at rest; tampering detected by a hash chain.
  • Policy changes are versioned and validated before they apply.

Data model

  • agents: name, key_hash, key_prefix, created_at
  • audit_log: ts, agent, tool, decision, risk, reason, latency_ms, payload_enc, findings_json, prev_hash, row_hash
  • approvals: audit_id, agent, tool, reason, payload_enc, status, decided_at, result
  • policy_versions: ts, author, policy_json
  • eval_runs: ts, total, accuracy, recall, fpr, avg_ms, p95_ms

Tech stack and roadmap

  • Node.js 22 HTTP server, built-in SQLite and crypto, no third-party packages.
  • Vanilla JS dashboard served by the same server.
  • CI with GitHub Actions running the test suite; Docker image for deployment.
  • Next: an ML classifier for injection, notifications for pending approvals, per-tenant policies, Postgres.
